Control & data paths

System Topology

Coordination flows through routers and CAS queues; steady-state file reads bypass the router directly to HRW-selected Pebble storage nodes, while deployment workers pull work with zero inbound deploy ports.

Design decisions

Six architectural bets
that define the stack.

Bet 01 · Guardian + MonoFS + KVS

Filesystem-as-database & pull-based CAS leases

Guardian runs no Postgres, etcd, or inbound worker deployment channel. Partitions, intents, runtime state, and queues are versioned CAS files in MonoFS backed by embedded Raft KVS.

  • Reconciler compiles intent joins and asset dependsOn DAGs, resolving ${intent.X.outputs.KEY}.
  • Tasks land in /.queues/<pusher>/; pushers CAS-create .claims/<taskID>.json with a 5-minute lease (30m stale cutoff).
  • DESTROY executes in reverse dependency order; observed intents stay strictly read-only via :19090/:19091.
Bet 02 · MonoFS + Packager

Client-side HRW sharding & headless writable overlays

Hot steady-state reads never hop through the router. monofs-client fetches topology once, builds a local weighted Rendezvous ring, and hashes paths directly to monofs-server:9000.

  • Local edits land in a per-session NutsDB overlay; --headless serves the identical workspace over a Unix socket without /dev/fuse.
  • Cold content lives in Packager Indexed-Tail archives (ChaCha20-Poly1305 + zstd), retrieving any file in 2–3 HTTP byte-range requests.
  • PathIndex deduplicates directory prefixes (100K files in ~1.2 MB vs ~6.2 MB flat map).
Bet 03 · Doctor

One-way pre-WAL privacy funnel & unified query plane

Doctor owns no custom segment format — it writes Parquet + Bluge chunks into MonoFS logengine while guaranteeing raw secrets and unmasked PII never hit disk.

  • Privacy runs during OTLP flattening before WAL append: secret keys/bearer/JWTs become [REDACTED]; identity/PCI fields become HMAC tok_<16 hex>.
  • Independent per-signal fsync WAL buffers return 429 / ResourceExhausted cleanly on backpressure.
  • One query service serves native JSON, Prometheus, Loki, Tempo, DuckDB SQL, and leader-leased recording rules (30s CAS lease).
Bet 04 · sqlagregator

Two-phase federated SQL with coverage guarantees

sqlagregator compiles restricted SELECT queries into an AST, binds catalog endpoints, and pushes partial aggregations down to native backend dialects before merging in pure Go.

  • Five emitters: MonoFS DuckDB, ClickHouse (attributes['...']), BigQuery REST, CloudWatch Omni, and Logs Insights (FROM_UNIXTIME).
  • Time-shard pruning skips irrelevant backends; excluding a healthy shard fails closed with coverage_gap unless -allow-partial is set.
  • Router enforces loaded access policy via --sql-require-policy (default true) and user sql scopes.
Bet 05 · Doctor Federation Controller

Scoped multi-account federation for 50k pushers / 150k targets

A dedicated controller builds 500-target SHA-256 catalog shards and 256 AES-256-GCM token shards under a 90s MonoFS leader lease so query nodes never load monolithic catalogs or raw secrets.

  • atomic.Pointer[managerState] guarantees zero-tear hot-swaps; corrupt shards preserve the last-known-good catalog.
  • Lazy token resolution coalesces via singleflight with generation bumps so a stale 401 never overwrites a rotated token.
  • Global 64 / per-query 8 inflight cap + 2-strike per-target circuit breakers; unscoped fleet queries fail fast with HTTP 422.
Bet 06 · LB-Edge

Ephemeral L4 registry with automatic re-registration

LB-Edge discards state persistence altogether. Four compact Go binaries reconstruct routing state from Kubernetes Endpoints informers and LB_BOOTSTRAP.

  • Multi-port Kubernetes Services match the exact Service port backing guardian.intent/external-port so traffic never round-robins across unrelated ports.
  • Proxy polls GET /services every 2s; removed backends stop taking new TCP connections and drain to zero active streams.
  • 3 consecutive dial failures trip the passive breaker until the next healthy snapshot refreshes the pool.

Operational resilience

Failure Modes & Recovery

Documented degradation paths for every critical plane — verified by unit, chaos, and kill-node soak tests.

Failure Scenario Immediate Blast Radius Built-in Recovery Behavior
MonoFS storage node killed Reads/writes assigned to that HRW shard miss Router assigns failover node + TTL'd file list; delayed rebalance after ~10m; clients re-route seamlessly on return (verified in kill node-c soak)
MonoFS router unavailable New mounts, ingests, publishes, Guardian writes pause Steady-state client reads continue directly via cached local HRW ring; clients re-register on router recovery
Guardian pusher offline / crashed In-flight apply stalls; tasks accumulate in queue .claims/<taskID>.json 5-minute lease expires cleanly; surviving pusher reclaims and resumes up to 30m stale cutoff
Concurrent Guardian write / ListDir race A concurrent write hides a .state entry mid-scan Runtime skips that single intent for the cycle instead of failing the partition; Guardian version misses < 10m return transient Unavailable

Documented Boundaries & Non-Goals

Explicit limits in the current codebase

  • FUSE vs headless workspace: The FUSE projection is a practical POSIX subset with limited locking and mmap semantics. Containers without /dev/fuse should run monofs-client --headless. An experimental C kernel module exists in-repo but is not the supported path.
  • Guardian rollbacks & CDK units: Failed applies record rollbackTo/rollbackReason and preserve the pushed desired manifest for retry — restoring an older archive tag is an explicit operator command. CDK-expressible intents collapse into one stack asset unit.
  • LB-Edge is L4 TCP only: No HTTP path routing, SNI termination, or active health probes beyond the 3-dial-failure passive circuit breaker.
  • Observability access control scope: Logs, traces, and federated SQL enforce per-partition compiled ACLs; metrics remain intentionally platform-visible without per-tenant row filtering.
